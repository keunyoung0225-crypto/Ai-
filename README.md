# 2026년 모아보는 정책한눈

수의계약·위수탁지원사업 등 2026년 정책 공고를 한곳에서 검색하는 웹앱입니다.

## 주요 기능
- **지역별 공고 지도**: 첫 화면의 대한민국 지도에서 시·도를 눌러 그 지역 공고만 보기. 공고가 많을수록 진한 색, 숫자로 건수 표시,
  옆 패널에 지역의 공고·접수 중·마감 임박 건수와 마감이 가까운 공고 3건. 지역 버튼 목록으로도 고를 수 있음
- **검색유형 버튼**: 전체 / 수의계약 / 위수탁지원사업 (누르면 바로 필터링)
- **숫자로 바로 보기**: 위쪽 `전체 공고`·`접수 중`·`마감 임박` 숫자를 누르면 그 공고만 목록에 표시 (접수 중·마감 임박은 마감이 가까운 순). 지도 옆 지역 패널의 숫자도 같은 방식이며, 결과 위 `접수 중만 ×`로 해제
- **키워드 검색**: 공고명·사업내용·지원대상·기관을 한꺼번에 검색 (띄어쓰기로 여러 단어를 넣으면 모두 포함된 공고)
- **최근 검색 공고**: 마지막으로 검색한 키워드를 기억해, 다음 방문 때 그 키워드에 맞는 공고 3건을 위쪽에 표시 (이 기기 브라우저에 저장)
- **조건 검색**: 공고명, 공고일(기간), 주체기관, 사업기간(기간)
- **결과 표**: 공고일 · 주체기관 · 사업기간 · 정책사업내용 · 예산 · 지원마감일
  - 정책사업내용 칸에 공고명(굵게)과 사업 요약을 함께 표시
  - 예산은 `12억 5,000만원` 형식으로 표시
- **정렬**: 공고일·예산·지원마감일 머리글 클릭 (모바일은 정렬 메뉴)
  - 지원마감일 정렬 시 이미 마감된 공고는 항상 맨 뒤
- **더보기**: 10건씩 나눠 표시
- **상세 보기**: 공고명을 누르면 지원대상 등 전체 정보 표시
- **신청 페이지 연결**: 공고마다 신청 페이지 주소를 보여 주고, 누르면 새 창으로 이동 (표의 `신청하기`, 상세 보기의 `신청하러 가기`)
- **지원 가능한 공고만**: 지원마감일이 지난 공고는 목록·지도·숫자에서 모두 빠짐
- **D-day 배지**: 마감 7일 이내는 빨간색
- **링크 공유**: 검색 조건·정렬·열어 둔 공고가 주소(URL)에 저장되어 그대로 공유 가능
- **모바일**: 좁은 화면에서는 표가 카드형 목록으로 바뀜
- **관심공고**: 공고명 옆 ☆을 눌러 저장, `★ 관심공고만`으로 모아 보기 (이 기기 브라우저에 저장)
- **마감 알림**: 관심공고 중 마감 7일 이내 공고를 화면 위쪽에 표시
- **엑셀 다운로드**: 현재 검색·정렬 결과 전체를 CSV(엑셀에서 열림)로 저장
- **비슷한 공고**: 상세 보기에서 같은 유형·기관·비슷한 제목의 공고 추천
- **화면 모드**: 오른쪽 위 버튼으로 자동 / 밝게 / 어둡게
- **광고 영역**: PC(1100px 이상)는 화면 왼쪽 세로 광고(기본 160×600, 아래 손잡이로 세로 크기 조절, 스크롤해도 따라옴), 휴대폰·좁은 화면은 맨 아래 고정 띠 광고(320×50, 닫기 가능)
- **접근성**: 키보드 초점 표시, '검색 결과로 바로가기', 움직임 줄이기 설정 존중
- **휴대폰 알림(앱 설치형, PWA)**: 사이트를 홈 화면에 추가하면 앱처럼 열리고, 관심 키워드에 맞는 새 공고를 매일 아침 9시에 알림으로 받음 (무료 앱 ntfy로도 가능, 아래 '휴대폰 알림' 참고)
- **매일 자동 갱신**: 매일 아침 구글 시트·CSV, 나라장터 API, 중소벤처기업부 지원사업(기업마당 API), 창업진흥원(K-Startup API)에서 공고를 모아 데이터 갱신, 새 공고에 `NEW` 표시 (아래 '공고 데이터 매일 갱신' 참고)

> 현재 공고 데이터(`data/policies.json`)는 **시연용 가상 데이터**입니다.

## API 연동
1. `js/data/adapters/`에 응답을 공고 형식으로 바꾸는 함수를 만들고 `adapters/index.js`에 등록합니다.
   공고 형식은 `data/policies.json`과 같으며(`id`, `category`, `title`, `announceDate`, `agency`,
   `period{start,end}`, `content`, `target`, `budget`, `deadline`, `applyUrl`(신청 페이지), `url`(공고 원문)), 날짜는 `20260302`·`2026.03.02` 같은
   표기도 자동으로 정리됩니다.
2. `js/config.js`에서 `DATA_SOURCE = 'api'`, `API_CONFIG.endpoint`·`adapter`를 설정합니다.
3. API가 실패하면 `fallbackToJson: true`일 때 샘플 데이터로 대체하고 화면 하단에 안내합니다.

> **주의**: 공공데이터포털 등 인증키가 필요한 API는 키를 이 앱(브라우저 코드)에 넣지 마세요.
> 누구나 볼 수 있습니다. 또 많은 공공 API는 브라우저에서 직접 호출하는 것(CORS)을 막아 둡니다.
> 자체 서버(프록시)에서 키를 붙여 호출하고, `endpoint`에는 그 서버 주소를 적는 방식을 권장합니다.
> 실제 공공 API는 아직 연결해 보지 않았으므로, 연결 시 응답 필드 이름을 API 문서로 확인해야 합니다.

## 공고 데이터 매일 갱신
매일 08:30(한국 시각)에 GitHub Actions가 `scripts/update-data.mjs`로 공고를 모아 `data/policies.json`을 갱신하고
저장소에 저장합니다. 사이트(GitHub Pages)는 저장된 데이터로 자동으로 다시 만들어지고, 이어서 휴대폰 알림을 보냅니다.

### 데이터 출처 켜기
`scripts/sources.json`에서 쓸 출처의 `"enabled"`를 `true`로 바꾸고, 필요한 값을 GitHub 저장소
**Settings → Secrets and variables → Actions → Secrets**에 등록합니다. 여러 출처를 함께 써도 됩니다.

| 출처 | 내용 | 등록할 Secret |
|---|---|---|
| `sheet` (구글 시트·CSV) | 직접 정리한 공고. 수의계약·위수탁지원사업 모두 가능 | `POLICY_SHEET_CSV_URL` |
| `nara` (나라장터 API) | 조달청 나라장터의 수의계약 공고 자동 수집 | `DATA_GO_KR_KEY` |
| `mss` (기업마당 API) | 중소벤처기업부 지원사업 공고 자동 수집 → `위수탁지원사업` | `BIZINFO_API_KEY` |
| `kstartup` (K-Startup API) | 창업진흥원 창업지원사업 공고 자동 수집 → `위수탁지원사업` | `DATA_GO_KR_KEY` (나라장터와 같은 키) |

**구글 시트로 관리하기 (권장)**
1. `templates/policies-template.csv`를 구글 시트로 가져옵니다. 열: 공고ID(선택), 검색유형, 공고명, 공고일, 주체기관,
   사업기간, 정책사업내용, 지원대상, 예산(원), 지원마감일, 신청URL(선택), 공고URL(선택), 지역(선택)
   - **지역**은 `서울`, `경기`, `경상남도` 같은 시·도 이름입니다. 비워 두면 주체기관 이름(예: `경기도 수원시`)에서 찾고,
     찾지 못하면 지도에는 표시되지 않습니다(목록·검색에는 나옴).
   - **신청URL**은 신청서를 내는 페이지, **공고URL**은 모집공고문 원문 페이지 주소입니다. `https://`로 시작하는 주소만 표시됩니다.
   - 사이트의 **엑셀 다운로드** 파일도 같은 열 이름이라 그대로 가져와 고칠 수 있습니다.
   - 예산은 `30000000`, `3,000만원`, `12억 5000만원` 모두 됩니다. 검색유형은 `수의계약` 또는 `위수탁지원사업`.
   - 공고명을 나중에 고칠 수 있다면 **공고ID**를 넣어 두세요. (없으면 공고명·기관·공고일로 ID를 만들어서, 고치면 새 공고로 인식)
2. 시트 메뉴 **파일 → 공유 → 웹에 게시**에서 시트를 **쉼표로 구분된 값(.csv)** 으로 게시하고 주소를 복사합니다.
3. 그 주소를 Secret `POLICY_SHEET_CSV_URL`로 등록하고 `sources.json`의 `sheet`를 켭니다.

**나라장터 API 연결**
1. 공공데이터포털(data.go.kr)에서 **조달청_나라장터 입찰공고정보서비스** 활용 신청을 하고 인증키를 받습니다. (화면의 Encoding·Decoding 키 중 어느 쪽을 넣어도 됩니다)
2. 인증키를 Secret `DATA_GO_KR_KEY`로 등록하고 `sources.json`의 `nara`를 켭니다.
3. 계약 방법에 "수의"가 들어간 공고만 `수의계약`으로 가져옵니다. (`contractMethodIncludes`로 변경)

> ⚠ 나라장터 수집기는 실제 API로 시험하지 못했습니다. 처음 연결한 뒤 Actions 실행 결과를 확인하고,
> 오류가 나면 공공데이터포털 문서의 주소(`endpoint`)·기능 이름(`operations`)·응답 필드 이름을
> `sources.json`과 `scripts/collectors/naraBid.js`에 맞춰 주세요.

**창업진흥원 창업지원사업 연결 (K-Startup API)**
1. 공공데이터포털에서 **창업진흥원_K-Startup(사업소개,사업공고,콘텐츠 등) 조회서비스**를 활용신청합니다. (자동 승인, 1~2시간 뒤 사용 가능)
2. 인증키는 계정마다 하나라 나라장터용 Secret `DATA_GO_KR_KEY`를 그대로 씁니다. `sources.json`의 `kstartup`이 켜져 있으면 됩니다.
3. 모집 중(`rcrt_prgs_yn`이 N이 아닌) 공고만 `위수탁지원사업`으로 가져옵니다. (`onlyRecruiting: false`면 전부)
4. 지원 지역(`경기`, `전남광주` 등)은 지도에 표시되고 `전국`은 지역 없음으로 둡니다. 접수 시작일을 공고일로, 접수 종료일을 마감일로 씁니다.

> ⚠ K-Startup 수집기도 실제 API로 시험하지 못했습니다(시험용 가짜 서버로만 확인). 공고명 항목 이름을 문서로 확인하지 못해
> 후보 이름을 차례로 찾습니다. 실행 결과에 'K-Startup 공고명을 찾지 못함' 경고가 나오면, 경고에 적힌 항목 이름 중 공고명을
> `scripts/collectors/kstartup.js`의 `TITLE_FIELDS` 맨 앞에 넣어 주세요.

**중소벤처기업부 지원사업 연결 (기업마당 API)**
중소벤처기업부 지원사업 공고는 기업마당(bizinfo.go.kr)에 모여 있어, 기업마당 API로 가져옵니다.
1. 기업마당 누리집에 회원가입 후 **정책정보 개방 → API 목록 → 지원사업정보 API**에서 사용 신청을 하고 인증키를 받습니다.
2. 인증키를 Secret `BIZINFO_API_KEY`로 등록하고 `sources.json`의 `mss`를 켭니다.
3. 소관 부처가 `중소벤처기업부`인 공고만 `위수탁지원사업`으로 가져옵니다.
   - 다른 부처도 받으려면 `agencyIncludes`에 이름을 더합니다. 예: `["중소벤처기업부", "산업통상자원부"]` (비우면 기업마당 공고 전체)
   - 한 번에 받는 공고 수는 `count`(기본 500건, 최신 공고부터)입니다.
4. 사업 요약은 앞 200자만 보여 주고, 지역은 수행기관 이름(예: 경기테크노파크 → 경기)에서 찾습니다. 전국 사업은 지도에 표시되지 않습니다.
   기업마당은 사업기간·예산을 주지 않아 그 칸은 `-`로, '예산 소진 시까지' 같은 공고는 마감일 없이 표시됩니다.

> ⚠ 기업마당 수집기도 실제 API로 시험하지 못했습니다(시험용 가짜 서버로만 확인). 처음 연결한 뒤 Actions 실행 결과를 확인하고,
> 오류가 나면 기업마당 API 안내의 응답 필드 이름을 `scripts/collectors/bizinfo.js`에 맞춰 주세요.

### 갱신 규칙
- 처음 들어온 공고에는 수집한 날짜(`firstSeen`)를 기록하고, 사이트에서 이틀 동안 `NEW`로 표시합니다.
- **9시 알림은 그날 갱신에서 새로 들어온 공고**만 대상으로 합니다. 출처를 처음 연결한 날은 기존 공고가 한꺼번에
  들어오므로 알림을 보내지 않습니다.
- 실제 출처에서 공고가 들어오면 시연용 샘플 공고는 자동으로 지워집니다.
- **지원 가능한 공고만** 남깁니다. `removeClosed: true`(기본)면 지원마감일이 지난 공고는 받지 않고, 어제까지 접수였던 공고도 지웁니다.
  사이트 화면도 `js/config.js`의 `HIDE_CLOSED: true`로 마감 지난 공고를 보여 주지 않습니다. (마감일이 없는 공고는 그대로 표시)
- 마감일(없으면 공고일)이 `keepDays`(기본 365일)보다 오래된 공고는 지웁니다.
- 출처 하나가 실패해도 그 출처의 기존 공고는 유지하고 나머지는 갱신합니다. 모든 출처가 실패하면 작업이 실패로 표시됩니다.
- 공공기관 서버가 잠시 응답하지 않으면(`fetch failed` 등) 5초·20초 간격으로 최대 3번 다시 시도합니다. 그래도 안 되면 원인을 한국어로 보여 주고, 다음 실행 때 다시 받아옵니다.
- 실행 결과(출처별 수신·새 공고 건수)는 **Actions** 탭의 실행 기록에서 볼 수 있습니다.
- 출처를 하나도 켜지 않으면 `data/policies.json`을 직접 고치는 방식으로 쓸 수 있고, 이때 알림은 어제 공고일인 공고를 대상으로 합니다.

```bash
# 내 컴퓨터에서 확인 (저장하지 않고 결과만 출력)
POLICY_SHEET_CSV_URL="게시한 CSV 주소" node scripts/update-data.mjs --dry-run
```

새 출처를 붙이려면 `scripts/collectors/`에 수집기를 만들어 `collectors/index.js`에 등록하고 `sources.json`에 추가합니다.

## 휴대폰 알림 (매일 아침 9시)
관심 키워드에 맞는 공고가 새로 올라오면 매일 아침 9시(한국 시각)에 휴대폰으로 알려 줍니다.
서버 없이 **GitHub Actions**(매일 자동 실행)가 알림을 보냅니다. 받는 방법은 두 가지이고 함께 써도 됩니다.

| 방법 | 설명 |
|---|---|
| **앱 알림 (PWA, 추천)** | 사이트를 홈 화면에 추가하면 앱처럼 열리고 알림을 받습니다. 따로 앱을 설치하지 않습니다. |
| ntfy | 무료 알림 앱 ntfy를 설치해 받습니다. |

### 앱 알림(PWA) 설정 방법
사이트 오른쪽 위 **휴대폰 알림** 버튼을 누르면 아래 과정을 화면에서 안내하고, 필요한 내용을 만들어 줍니다.

**처음 한 번 (운영자)**
1. PC 크롬·엣지에서 사이트를 열고 **휴대폰 알림 → 알림 키 만들기**를 누릅니다. 공개 키·비밀 키가 만들어집니다.
   (키는 브라우저 안에서만 만들어지고 어디에도 보내지 않습니다)
2. 공개 키를 `js/config.js`의 `NOTIFY_CONFIG.webPush.vapidPublicKey`에 붙여 넣고 저장(커밋)합니다.
3. GitHub 저장소 **Settings → Secrets and variables → Actions → Secrets**에 등록합니다.
   - `VAPID_PUBLIC_KEY` = 공개 키
   - `VAPID_PRIVATE_KEY` = 비밀 키 (절대 코드나 채팅에 올리지 마세요)

**알림 받을 휴대폰마다**
1. 휴대폰으로 사이트를 엽니다.
   - **안드로이드**(크롬·삼성 인터넷): 그대로 진행해도 되고, 메뉴의 **홈 화면에 추가(앱 설치)** 를 하면 앱처럼 쓸 수 있습니다.
   - **아이폰·아이패드**(iOS 16.4 이상): Safari **공유 버튼 → 홈 화면에 추가** 후, 홈 화면의 **정책한눈** 아이콘으로 엽니다. (홈 화면에 추가해야만 알림을 받을 수 있습니다)
2. **휴대폰 알림** 창에서 관심 키워드를 입력하고 **이 기기에서 알림 켜기 → 허용**을 누릅니다.
3. 나타난 **알림 구독 정보**를 복사해 GitHub Secret `WEB_PUSH_SUBSCRIPTIONS`에 넣습니다.
   기기가 여러 대면 한 줄에 하나씩 붙여 넣습니다. (Secret은 다시 볼 수 없으니 기존 줄도 함께 넣어 다시 저장)
4. 설정 창의 **관심 키워드 설정**을 복사해 `alerts/subscriptions.json`에 저장(커밋)합니다.
5. (선택) **Variables**에 `SITE_URL` = 사이트 주소(예: Vercel 주소)를 추가하면 알림을 눌렀을 때 그 주소가 열립니다.
6. **Actions** 탭 → 매일 공고 갱신·알림 → **Run workflow**에서 시작 날짜(예: `2026-01-01`)를 넣고 실행하면 바로 시험 발송됩니다.

> 구독 정보를 아는 사람은 그 기기로 알림을 보낼 수 있으니 Secret에만 넣으세요.
> 알림을 끄거나 앱을 지운 기기는 발송 때 '구독 만료' 경고가 나옵니다. 그 기기에서 알림을 다시 켜고 Secret을 바꿔 주세요.

### ntfy로 받기 (다른 방법)
1. 휴대폰에 **ntfy** 앱을 설치합니다. (Play 스토어·App Store에서 "ntfy" 검색)
2. 사이트의 **휴대폰 알림 → 다른 방법: 무료 앱 ntfy로 받기**에서 만들어진 **알림 주제 이름**을 앱에서 구독하고, 테스트 알림을 확인합니다.
3. Secret `NTFY_TOPIC` = 알림 주제 이름을 추가하고, 관심 키워드 설정을 `alerts/subscriptions.json`에 저장합니다.

### 동작 방식
- `.github/workflows/daily.yml`이 매일 08:30에 공고를 갱신한 뒤 `scripts/notify.mjs`를 실행합니다.
  GitHub의 예약 실행은 몇 분~수십 분 늦을 수 있어 미리 실행합니다.
  - ntfy는 예약 발송으로 **09:00에 도착**합니다.
  - 앱 알림은 예약 발송이 없어 작업이 **09:00까지 기다렸다가** 보냅니다. (그동안 Actions 실행 시간이 쓰입니다. 공개 저장소는 무료, 비공개 저장소는 매달 무료 시간 안에서 하루 약 30분)
- 그날 갱신에서 새로 들어온 공고 중 키워드가 하나라도 맞는 공고를 모아 보냅니다. 맞는 공고가 없으면 보내지 않습니다.
  - 앱 알림은 **키워드마다 한 건씩** 옵니다. 제목 `[돌봄] 새 공고 2건`, 본문은 공고명(마감일)을 한 줄에 하나씩 (최대 4건, 나머지는 '외 n건').
    알림을 누르면 그 키워드로 검색한 사이트 화면이 열립니다. 키워드가 많으면 5건까지 보내고 나머지는 마지막 알림에 덧붙입니다.
  - ntfy는 한 건으로 모아서 오고, 제목에 맞은 키워드가 표시됩니다.
  키워드는 검색 화면의 키워드 검색과 같은 규칙입니다. (띄어쓰기로 나눈 단어가 모두 들어 있으면 일치)
- 사람마다 다른 키워드를 쓰려면 `subscriptions.json`에 항목을 추가하고 `webPushEnv`(또는 `topicEnv`)를 `WEB_PUSH_SUBSCRIPTIONS_2` 같은 새 이름으로 정한 뒤,
  같은 이름의 Secret을 등록하고 워크플로 파일의 `env`에도 한 줄 추가합니다.
- 앱 알림 발송에는 `web-push` 패키지를 씁니다. `scripts/package.json`에 있고 작업이 실행될 때 설치합니다. (사이트 화면에는 쓰이지 않음)

```bash
# 내 컴퓨터에서 확인 (보내지 않고 내용만 출력)
node scripts/notify.mjs --dry-run --since 2026-01-01
```

### 알아둘 점
- 예약 실행은 **main(기본) 브랜치에 병합된 뒤**부터 동작합니다.
- 실제 알림을 받으려면 위 '공고 데이터 매일 갱신'에서 데이터 출처를 켜야 합니다. (샘플 데이터에는 새 공고가 생기지 않음)
- 앱 알림은 `https://` 주소(Vercel, GitHub Pages)에서만 켤 수 있습니다.
- ntfy 주제 이름을 아는 사람은 누구나 그 알림을 볼 수 있습니다. 추측하기 어려운 이름을 쓰고 공개하지 마세요.
- 공개 저장소는 60일 동안 변경이 없으면 GitHub가 예약 실행을 멈춥니다. Actions 탭에서 다시 켤 수 있습니다.

## 광고 영역
`js/config.js`의 `AD_SLOTS`에서 설정합니다.

| 영역 | 보이는 화면 | 크기 |
|---|---|---|
| `side` | 너비 1100px 이상(PC): 화면 왼쪽, 스크롤해도 따라옴 | 160×600 (세로 250~900 조절) |
| `bottom` | 너비 1100px 미만(휴대폰·태블릿): 화면 맨 아래 고정, `×`로 닫기 | 320×50 |

- 비워 두면 "광고 영역" 빈 틀이 보입니다.
- **세로 크기 조절(`side`)**: 광고 틀 아래 손잡이를 위아래로 끌거나, 손잡이를 고른 뒤 키보드 ↑↓(20px씩)·Home(최소)·End(최대)로 조절합니다.
  조절한 높이는 이 브라우저에 기억되고, 손잡이를 두 번 누르면 기본 높이로 돌아갑니다. 화면보다 길어지지 않도록 자동으로 줄어듭니다.
  기본·최소·최대 높이는 `height`·`minHeight`·`maxHeight`, 손잡이를 없애려면 `resizable: false`로 설정합니다.
- `ads` 목록의 각 광고에 `imageUrl`(광고 이미지 주소)과 `linkUrl`(누르면 갈 주소, `https://`)을 채우면 그 이미지 광고가 나오고, 누르면 새 창으로 열립니다.
  - 광고 이미지는 저장소의 `images` 폴더에 올리고 `imageUrl: 'images/파일이름.jpg'`처럼 적으면 됩니다. (다른 사이트의 이미지는 `https://`로 시작하는 전체 주소)
- **광고 바꿔 보여 주기**: `ads`에 광고가 2개 이상이면 `rotateSeconds`(지금 30초)마다 다음 광고로 바뀌고, 마지막 다음에는 처음으로 돌아갑니다.
  - 두 번째 광고 자리는 이미 만들어 두었습니다. `images` 폴더에 **`ad-side-2.jpg`(PC 왼쪽, 160×600)**, **`ad-bottom-2.jpg`(휴대폰 아래, 320×50 비율, 640×100 권장)** 를 올리면 바로 번갈아 나옵니다.
  - 아직 올리지 않은 이미지는 건너뛰므로, 올리기 전에는 첫 번째 광고만 계속 보입니다. 다른 탭을 보는 동안에는 바뀌지 않습니다.
- `enabled: false`로 하면 그 영역을 숨깁니다.
- 애드센스 같은 광고 네트워크를 쓰려면 그 서비스가 주는 코드를 `js/components/adSlot.js`의 빈 틀 대신 넣으면 됩니다.
  (광고 네트워크는 사이트 심사와 `ads.txt` 등 별도 절차가 필요합니다)
- 모든 광고에는 "광고" 표시가 붙습니다.

## 저장 데이터
관심공고, 화면 모드, 최근 검색 키워드는 이 기기의 브라우저(localStorage)에만 저장됩니다.
다른 기기와 공유되지 않으며, 브라우저 기록을 지우면 사라집니다.

자세한 개발 계획은 [PLAN.md](PLAN.md)를 참고하세요.
